# Changelog

Versions follow [semantic versioning](https://semver.org/). Until 1.0.0 the product is in staging: a minor
step (0.x.0) may change config files, and the upgrade step migrates them (see `docs/DECISIONS.md`); a
patch step (0.0.x) is a build of the next backlog task or a fix. The release workflow refuses to publish a
tag that has no entry here. Images are tagged with the exact version; there is no `latest`.

## 0.0.58

- **Fixed: most syslog lines from real devices were stored as parse failures.** Some devices (UniFi gateways, switches, and access points) end every datagram with a newline, and the header pattern could not match before it, so the line was kept raw with its event time guessed from when it arrived. On one real network that was about 70% of all lines. Line endings are now trimmed before parsing (the archive still keeps each line exactly as received). Two tests cover the newline and CR LF cases. Lines already stored keep their guessed times; new lines get their real ones.
- **Fixed: the Unraid collector failed every hour on a server whose drives were asleep.** Reading disk health woke the drives and took 45 seconds, and the 10-second request limit gave up each time. The disk request now has its own longer limit (`slow_request_timeout_s`, 60 seconds by default, a field on the Collectors page); the others keep 10. A timeout now says which request was slow ("no answer within 10 s [while reading disks]"). Reading disk health can wake sleeping drives, so the setting's help suggests a daily interval if you care about spin-down.

## 0.0.42

Found by running the agent test cases against a real model (an 8B model on a local Ollama), and fixed:

- **Citations written in the other common spellings were being thrown away.** `[r1]`, `[ref: r1]`, `[refs: r1, r2]`, and `(ref:r1)` are now accepted and written back as `[ref:r1]`; a citation after the full stop (`... slower. [ref:r1]`) now belongs to the sentence before it; a citation with nothing before it asserts nothing and is dropped. Tool results are now labelled `[ref:r1]` (they were `[r1]`), so the model copies the right form. A citation to a result that does not exist or failed still drops the sentence.
- **Tool arguments are tolerant of small-model spellings**: `"true"` for true and `"5"` for 5 are accepted. The model had sent `pending_only: "true"`, been refused three times, and never saw the inventory.
- **Two shipped prompts rewritten and measured.** Investigator: every sentence must end with a citation and nothing may be added that a result does not say (score 79 to 95 over three runs each; citation rate 31% to 85%). Ask the lab: same rule plus never name a tool that is not in the list (the old prompt scored 10 in four runs out of four, with nothing cited; the new one averages 96).
- A second ask-the-lab test case (the inventory) and a check that the answer does not name tools that do not exist; the triage case now allows both an ignore and a playbook proposal.

## 0.0.39

Task 29: the four agents (still off by default; each needs `ai.yaml` + `features.agents` and its own `enabled`).

- **Investigator**: queued after the daily run for each story whose kind ranks at or above `on_finding_rank_at_least` (three a day at most, none repeated within three days), or on demand. Its cited note shows on the Findings page, on the host's detail page (within the 150-line limit), and through MCP (`get_finding`, and a flag in `list_findings`).
- **Triage**: queued for the busiest new signatures after learning ends; answers with a JSON verdict per signature (noise, watch, concern, unsure), each needing a real citation. A noise verdict may carry an ignore rule and a concern verdict a playbook rule; the product builds the file change itself and records it as a proposal.
- **Tuner**: queued weekly; suggests up to three single-value changes (for example `lifecycle.renotify_hours`). The product applies each to a copy, replays the last week with and without it, and writes those numbers into the proposal itself.
- **Ask the lab**: a question box on the AI page; the cited answer appears when the worker has run it.
- **Safety rules, in code** (`agentguards.py`, run for every proposal): triage can only add ignore or playbook rules and never ignores disk, authentication, or security events (refused if the rule names one, would also match a recent line about one, or is too broad); the tuner never touches disk, parity, SMART, storage, or absence settings, never suppresses a kind, and is refused if the replay shows an acknowledged, snoozed, urgent, or protected finding would be hidden. Triage and tuner cannot use the `propose_change` tool.
- `brief agent verdicts`; a Triage verdicts table on the AI page.

## 0.0.38

Task 28: the proposals workflow.

- A proposal (file, complete new text, reason, evidence) is a record made by an agent (`propose_change`) or an MCP client with the new `propose` scope. Making one changes no config file. Only `ignore.yaml`, `priorities.yaml`, and `playbook.yaml` can be proposed, the new text must pass the pipeline's own validator, one run may make three, and twenty may wait. An agent's evidence must cite real tool results.
- The **Proposals** section of the AI page shows each one with its reason, evidence, and a diff against the file as it is now. Approve saves it through the config editor (checked again, kept as a version for rollback, audited); reject is audited too. A proposal made against an older version of the file is closed, an invalid one cannot be approved, and an undecided one expires after 14 days. `brief proposal list|show|approve|reject` does the same from a shell.
- New tool `get_config` (needs `logs`) lets an agent read the files it may propose against. `propose` is never in the default scope and never allowed for a cloud client; cloud agents are not offered either tool.

- Presence and hourly traffic per device from the UniFi API (`clients`, `traffic`), and gateway DNS and access point join and leave lines from syslog (`client_logs`).
- Profiles are enforced where data would be stored: `ignore` keeps nothing (its log lines are only counted as suppressed), `security_only` (the default for an unlisted device) keeps that the device exists and its traffic volume, `full` also keeps DNS detail and hourly presence. Client log lines of non-`full` devices stay out of the signature counts and samples.
- Detectors `new_device`, `traffic_spike` (judged against the device's own usual day), and `odd_hours`, with playbook advice; hourly rows roll up to daily rows after 90 days. Migration none (tables from 0007).
- `scripts/e2e_collector.py` now sends DNS and join lines through Vector in the real image and checks what each profile kept.

## 0.0.30

Task 20: the UniFi collector (off by default; needs a read-only API key from the Network application).

- Reads devices, models, firmware, update availability, and uplinks from the UniFi Network Integration API into inventory and the network map tables; sensors for device, offline, and update counts.
- Firmware is also read from the `<mac>,<model>-<firmware>` token in switch, access point, and PDU syslog headers (new `device_header` table, written once per ingest cycle, migration 0009), so inventory has it when the API is unreachable or no key is set.
- Detectors: `firmware_pending` (an update waiting; after 30 days it becomes `version_behind`) and `new_infrastructure` (a gateway, switch, access point, PDU, camera, or server first seen after discovery settled), with playbook advice.
- The Unraid and UniFi collectors now share their HTTP and topology code; `detectors_disks` and `detect_disks` are now `detectors_hw` and `detect_hw`.
- `scripts/e2e_collector.py` also runs the UniFi path (fake API, plus firmware arriving in a syslog header).

## 0.0.29

Task 19: the Unraid collector (off by default; needs a read-only API key per server).

- Reads each server's GraphQL API: array state, disks with temperature and SMART verdict, parity check history, containers and VMs, unread warnings, OS and plugin versions. Servers are independent (an unreachable one reports `unraid_<id>_reachable` 0 and the others still update); a field or section a server does not have is dropped, not fatal.
- Optional `smart_source: smartctl_files` reads reallocated, pending and CRC attributes from files a User Script writes (`deploy/unraid-smart-export.sh`), because the API does not report the attribute table.
- Detectors: `smart_failing`, `smart_trend`, `crc_rising`, `disk_temp`, `parity_slow`, `unraid_warning`, `version_behind`, with playbook advice and buckets.
- Rows for the network map (server, containers, VMs), inventory, and per-server sensors. Migration 0008.
- `brief collector test unraid` reports per server and per section what answered. New end-to-end check `scripts/e2e_collector.py` runs the whole path against a fake Unraid API.

## 0.0.28

Task 18: the Phase 2 framework. No collector ships yet (Tasks 19 to 23 add them), and every one is off.

- Collector contract and framework: `collectors.yaml` is validated (a credential written into it is refused, keys come from template variables), enabled collectors run when due from the hourly job, each isolated with its own timeout; a failing one reports `collector_<name>_ok` 0 with a safe reason and keeps its last good numbers. Enabling or disabling one adds or removes its sensors, `/metrics` lines and API values with no other change. `brief collector list|test|run`.
- Migration 0007: the Phase 2 tables (disks, SMART readings, inventory, clients, DNS, power, topology).
- Playbook engine: `playbook.yaml` rules turn findings into advice with structured conditions (no code, regexes with nested repetition refused); the advice shows in the brief and a rule id can be routed in `priorities.yaml`.
- `metric_drift` detector: any collector metric whose recent mean moves far from its own earlier mean.
- `collectors.yaml`, `map.yaml` and `agents.yaml` are now validated, guarded with a last-good fallback, and editable in the config editor.

## 0.0.27

Task 17: packaging and release.

- Release workflow: a tag runs every check, then builds and pushes the image to the container registry under the exact version tag (never `latest`), and refuses a tag that differs from the program version or has no entry here.
- Unraid template (`deploy/unraid-template.xml`) and compose references for all three network modes: own IP on `br0` (default), host, bridge with port mappings.
- Config files are brought up to the current schema on upgrade (`brief.confmigrate`): a copy of the config folder is saved to `/state/config-backups/` first, a downgrade is noticed and never touches files.
- `deploy/README.md` rewritten as the install and upgrade guide.
