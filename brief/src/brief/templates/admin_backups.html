Download a backup

One file with your config files, a consistent copy of the database, and the signature miner's state. It does not include the raw log archive, the TLS key, or the event files.

Treat it like a password: the database holds the admin password hash and sessions.

{{ icon('archive') }}Download backup

Ask for help: a support bundle

A diagnostics file you can send to someone, with the install's names taken out. It holds structure and numbers (the status, the shape of your config files, counts of senders, alerts and calls), never log lines or message text, and every address, MAC, domain, name, and secret is replaced by an alias such as <ip-1>. It checks itself before it is written, and is not made at all if anything private is left.

{{ icon('shield') }}Download support bundle

To turn an alias in a reply back into a name, run brief support-bundle --map aliases.json and keep that file private.

Restore the config from a backup

Only the config files are applied, one at a time through the same checks as the config editor; if one is not valid, nothing changes. To put the database back, stop the container and replace baseline.db in the appdata state folder with the one in the backup.
